User roles

  • Parent - real account (Supabase Auth), owns the subscription (once 4th MVP's payment system exists), sees their child(ren)'s results/KPIs.
  • Child - lightweight, parent-managed account (nickname + password), no billing relationship.
  • Teacher/tutor - deliberately deferred, not core to this MVP's data model.

#76 Done

Parent + child authentication

Story — As a parent, I want to own a real account and add my child(ren), so their results are tied to something real instead of a typed access code.

Acceptance Criteria

  • Parent sign-up/sign-in via Supabase Auth (email/password) - DONE, frontend/app/components/ParentAuth.jsx, direct against Supabase, never routed through the backend.
  • Parent can add/list children, each with their own lightweight nickname + password - DONE, new children table + backend/children.py. Password bcrypt-hashed, never returned to any caller.
  • Child login is a password gate under the parent's session, not a second independent auth system - DONE, deliberate design decision (see card footer) matching Squla/Junior Einstein's own shape.
  • Every attempt is tied to a real, ownership-checked child_id - DONE, attempts.student_id (free-text) replaced with a real FK attempts.child_id; every backend endpoint touching a specific child_id re-verifies parent ownership on every call, not just at picker time.
  • RLS tightened now that real identity exists - DONE, resolves old ticket #51's flagged gap for the tables this ticket touches (children/attempts/attempt_steps now parent-owned policies, not the "any authenticated session" MVP-permissive baseline). problems/misconception_rules/hints correctly untouched - shared content, nothing to scope per-parent.
  • Session persistence: stays logged into the last-selected child - DONE, localStorage, same pattern the old StudentCode.js stub used.
  • Frontend test framework chosen + real coverage for the new auth components - DONE, Vitest + React Testing Library (this repo's first frontend test suite ever - previously zero infrastructure, flagged as an open decision in .claude/plans/test-pyramid-design.md), 14 tests across ParentAuth/ChildPicker/ActiveChildHeader.
Depends on: nothing (first 3rd MVP ticket) · Blocks: dashboard, KPIs, 4th MVP's payment system · Deliberately deferred, not this ticket: GDPR/AVG consent flow (separate topic, explicitly parked), teacher/tutor role, a "forgot password" UI flow for parents (Supabase Auth supports it natively, fast follow if wanted) · See decision-log.md's "authentication design" entry for the full options table (client-only vs. also-a-Supabase-Auth-user for children) and why the lightweight-password-gate shape won.
